    5.1Maps

    The measurement model needs a map

    The measurement model p(zt∣xt,m)p(z_t \mid x_t, m)p(zt​∣xt​,m) describes how sensor readings are generated from the robot pose xtx_txt​ and the environment map mmm. A map is a list of objects in the environment and their properties, m={m1,m2,…,mN}m = \{m_1, m_2, \ldots, m_N\}m={m1​,m2​,…,mN​}. Two kinds of index are used:

    • Feature-based maps: nnn is a feature index and mnm_nmn​ holds the Cartesian location (and possibly a signature) of the feature. Compact, and natural for landmarks, poles, corners, fiducials.
    • Location-based maps: nnn corresponds to a specific location, for example a grid cell mx,ym_{x,y}mx,y​. Volumetric: they describe free space as well as objects, which is what planners need.

    Measurements are many values, assumed independent

    A modern sensor returns many values per reading: a 2D LiDAR gives KKK = 360 to 2000 ranges, zt={zt1,…,ztK}z_t = \{z_t^1, \ldots, z_t^K\}zt​={zt1​,…,ztK​}. The measurement model assumes the individual beams are conditionally independent given pose and map:

    p(zt∣xt,m)=∏k=1Kp(ztk∣xt,m).p(z_t \mid x_t, m) = \prod_{k=1}^{K} p(z_t^k \mid x_t, m).p(zt​∣xt​,m)=k=1∏K​p(ztk​∣xt​,m).

    This is an idealisation. Beams are correlated through people not in the map, map errors and approximations in the model itself. Its practical consequence is overconfidence: 1000 beams multiply 1000 slightly wrong likelihoods. Practitioners subsample beams (Nav2 AMCL uses 60 of the scan by default) or raise the product to a power below one.

    TLO1 asks you to discuss the basic measurement algorithm: for each beam compute its individual likelihood, then multiply (or add log-likelihoods). All the models in this chapter differ only in how they compute the per-beam term.

    5.2Beam models of range finders

    Four sources of range error

    The beam model is a physical model of a single range beam of a laser or sonar. Given the pose and map, ray casting gives the true range to the nearest obstacle, ztk∗z_t^{k*}ztk∗​. TLO3 asks you to explain the four types of measurement error a real reading ztkz_t^kztk​ can have:

    1. Correct range with local noise phitp_{hit}phit​: limited resolution, atmospheric effects, surface reflectance. A Gaussian centred on z∗z^*z∗ with standard deviation σhit\sigma_{hit}σhit​, truncated to [0,zmax][0, z_{max}][0,zmax​].
    2. Unexpected objects pshortp_{short}pshort​: people, carts and other objects not in the map return readings shorter than z∗z^*z∗. The probability of being blocked grows with distance, so it is an exponential with parameter λshort\lambda_{short}λshort​, truncated at z∗z^*z∗.
    3. Failures pmaxp_{max}pmax​: specular surfaces, glass, black objects or sunlight make the sensor return its maximum value zmaxz_{max}zmax​. A point mass at zmaxz_{max}zmax​.
    4. Random measurements prandp_{rand}prand​: cross-talk, sonar multipath and phantom readings. Uniform over [0,zmax][0, z_{max}][0,zmax​].

    This list also answers review question 2 on the sources of noise and uncertainty (ISA-2 question 3c).

    The mixture density

    The four components are combined with weights that sum to one, zhit+zshort+zmax+zrand=1z_{hit} + z_{short} + z_{max} + z_{rand} = 1zhit​+zshort​+zmax​+zrand​=1:

    p(ztk∣xt,m)=zhit phit+zshort pshort+zmax pmax+zrand prandp(z_t^k \mid x_t, m) = z_{hit}\,p_{hit} + z_{short}\,p_{short} + z_{max}\,p_{max} + z_{rand}\,p_{rand}p(ztk​∣xt​,m)=zhit​phit​+zshort​pshort​+zmax​pmax​+zrand​prand​
    phit=η N(ztk; ztk∗,σhit2),pshort=η λshorte−λshortztk (ztk≤ztk∗),prand=1zmaxp_{hit} = \eta\,\mathcal{N}(z_t^k;\ z_t^{k*}, \sigma_{hit}^2),\quad p_{short} = \eta\,\lambda_{short}e^{-\lambda_{short}z_t^k}\ (z_t^k \le z_t^{k*}),\quad p_{rand} = \frac{1}{z_{max}}phit​=ηN(ztk​; ztk∗​,σhit2​),pshort​=ηλshort​e−λshort​ztk​ (ztk​≤ztk∗​),prand​=zmax​1​

    Drawbacks of the beam model

    Review question 1 and ISA-2 question 2a ask for the major drawbacks. Write these five:

    1. Lack of smoothness: in cluttered places a small change of pose changes z∗z^*z∗ abruptly (a beam that just misses a table leg), so p(z∣x)p(z \mid x)p(z∣x) is spiky and particle filters need many particles.
    2. Computational cost: every beam of every particle needs a ray cast, typically O(range/resolution)O(\text{range}/\text{resolution})O(range/resolution) cells. Precomputing z∗z^*z∗ over a pose grid helps but costs memory.
    3. Overconfidence from the independence assumption.
    4. Sensitivity to map errors: a door modelled closed but actually open produces a long reading that falls behind the wall and is scored only by prandp_{rand}prand​.
    5. Parameters depend on the environment: zshortz_{short}zshort​ is large in crowds and small in empty warehouses, so a single tuning rarely fits all.

    5.3Likelihood fields for range finders - concepts

    Score the endpoint, not the ray

    The likelihood field (end-point) model gives up the physical ray-casting explanation. It projects the end point of each beam into the map and scores it by the distance distdistdist from that end point to the nearest obstacle:

    xzk=x+xk,senscos⁡θ−yk,senssin⁡θ+ztkcos⁡(θ+θk,sens)x_{z^k} = x + x_{k,sens}\cos\theta - y_{k,sens}\sin\theta + z_t^k\cos(\theta + \theta_{k,sens})xzk​=x+xk,sens​cosθ−yk,sens​sinθ+ztk​cos(θ+θk,sens​)
    yzk=y+yk,senscos⁡θ+xk,senssin⁡θ+ztksin⁡(θ+θk,sens)y_{z^k} = y + y_{k,sens}\cos\theta + x_{k,sens}\sin\theta + z_t^k\sin(\theta + \theta_{k,sens})yzk​=y+yk,sens​cosθ+xk,sens​sinθ+ztk​sin(θ+θk,sens​)

    where (xk,sens,yk,sens,θk,sens)(x_{k,sens}, y_{k,sens}, \theta_{k,sens})(xk,sens​,yk,sens​,θk,sens​) is the sensor mounting pose on the robot. The beam likelihood is a mixture of a zero-centred Gaussian on the distance and a uniform term:

    p(ztk∣xt,m)=zhit N(dist; 0,σhit2)+zrandzmax,p(z_t^k \mid x_t, m) = z_{hit}\,\mathcal{N}(dist;\ 0, \sigma_{hit}^2) + \frac{z_{rand}}{z_{max}},p(ztk​∣xt​,m)=zhit​N(dist; 0,σhit2​)+zmax​zrand​​,

    and max-range readings are simply discarded. Distances to the nearest obstacle are precomputed once for the whole map with a distance transform and stored in a lookup table, so each beam costs O(1).

    What the likelihood field looks like

    The model has three components compared with the beam model's four: noise (phitp_{hit}phit​ on the distance), failures (max readings ignored) and random measurements. It does not model unexpected short readings explicitly; a person in front of a wall simply produces an endpoint far from any map obstacle, which the uniform term absorbs.

    Use cases and problems of the likelihood field

    Use cases. The likelihood field is the default model of AMCL in ROS and Nav2 (laser_model_type: likelihood_field), and the same idea underlies scan matchers in Cartographer and Hector SLAM, which maximise the sum of a smoothed occupancy value at scan endpoints.

    CriterionBeam modelLikelihood field
    Physical basisRay casting through free spaceNone; endpoint heuristic
    Smoothness in posePoor in clutterGood
    Cost per beamRay castOne table lookup
    Unexplored / free spaceCorrectly uses itIgnores it
    Short readings from peopleModelled by pshortp_{short}pshort​Absorbed by prandp_{rand}prand​
    Problems
    Because only endpoints are scored, a beam that passes straight through a wall in the map is not penalised; the model cannot tell that the robot is on the wrong side of a thin wall. It ignores the information in max-range readings and treats unexplored space like free space. Remedies: treat unknown cells with a fixed low likelihood, or combine with a coarse beam check.

    5.5Correlation-based sensor models - concepts

    Matching maps instead of beams

    Correlation-based measurement models (map matching) turn the scan into a small local map mlocalm_{local}mlocal​, an occupancy grid in the robot frame built from the current (or last few) scans, and compare it with the global map mmm at the hypothesised pose. The standard similarity is the correlation coefficient over the overlapping cells:

    ρm,mlocal,xt=∑x,y(mx,y−mˉ)(mx,y,local(xt)−mˉ)∑x,y(mx,y−mˉ)2 ∑x,y(mx,y,local(xt)−mˉ)2\rho_{m, m_{local}, x_t} = \frac{\sum_{x,y}(m_{x,y} - \bar m)(m_{x,y,local}(x_t) - \bar m)}{\sqrt{\sum_{x,y}(m_{x,y} - \bar m)^2\ \sum_{x,y}(m_{x,y,local}(x_t) - \bar m)^2}}ρm,mlocal​,xt​​=∑x,y​(mx,y​−mˉ)2 ∑x,y​(mx,y,local​(xt​)−mˉ)2​∑x,y​(mx,y​−mˉ)(mx,y,local​(xt​)−mˉ)​

    with mˉ\bar mmˉ the average map value and the local map transformed into global coordinates by xtx_txt​. ρ\rhoρ lies in [−1,1][-1, 1][−1,1], so it is converted into a likelihood, for example p(mlocal∣xt,m)=max⁡(ρ,0)p(m_{local} \mid x_t, m) = \max(\rho, 0)p(mlocal​∣xt​,m)=max(ρ,0).

    Review question 4 asks you to explain this model: it compares two maps cell by cell, it naturally uses free space as well as obstacles, and it is the basis of grid-based scan matching.

    5.6Correlation-based sensor models - examples, use cases, problems

    Map matching in action

    Use cases
    Correlative scan matching (Olson, 2009) searches a 3D window of (x,y,θ)(x, y, \theta)(x,y,θ) exhaustively with multi-resolution grids and is used in Google Cartographer for loop-closure detection and in many industrial AMR localisers that align a scan to a reference map at start-up. Aerial and underwater robots correlate terrain elevation or sonar images the same way.

    Problems with correlation-based models

    • No physical noise model: the correlation is a heuristic similarity; it does not model unexpected objects or failures, so crowds degrade it.
    • Free space counts equally with obstacles: large empty areas correlate strongly everywhere, flattening the score in open halls.
    • Cost: building the local map and comparing many cells per pose hypothesis is more expensive than a likelihood-field lookup, though it can be vectorised.
    • Smoothness depends on grid resolution; maps are usually blurred first, which is equivalent to a likelihood field on both maps.
    • Symmetry: repetitive corridors and rack aisles give several equal peaks, so correlation alone cannot resolve global ambiguity.
    Discuss
    Why might an AMR in a warehouse with identical aisles correlate perfectly with the wrong aisle? Which extra information (feature signatures, odometry, fiducials) resolves it?

    5.7Feature-based sensor models - concepts

    Extract features, then model the features

    Feature-based models first reduce the raw measurement to a small set of features, f(zt)={ft1,ft2,…}f(z_t) = \{f_t^1, f_t^2, \ldots\}f(zt​)={ft1​,ft2​,…}, for example lines, corners, poles, reflectors or fiducial markers. Review question 5 and ISA-2 question 2b ask you to explain this model.

    Features drastically reduce computation (tens of features instead of hundreds of beams), and landmarks with known signatures make correspondence easy. The price is lost information: everything the extractor discards is invisible to the filter.

    Use cases and problems of feature-based models

    Real-life examples
    Fiducial markers (AprilTag, ArUco) on floors and walls give landmarks with unique signatures, so correspondence is trivial; many AGV and AMR products and drone landing pads use them. Reflector-based laser navigation, used on industrial AGVs for decades, measures range and bearing to retro-reflective targets with millimetre-level repeatability. Visual SLAM systems such as ORB-SLAM use image corner features as landmarks.
    Problems
    Feature extraction discards information and can fail in environments without clear features (open halls, foliage). Correspondence is often unknown and wrong associations are catastrophic for Gaussian filters (Chapter 6). Features are sensor-specific and extraction thresholds need tuning. Signatures are rarely unique in natural scenes.
