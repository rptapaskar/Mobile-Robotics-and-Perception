    7.1Occupancy grid mapping

    Mapping with known poses

    Chapters 5 and 6 assumed a map. Occupancy grid mapping builds one, assuming the robot poses are known (from ground truth, a motion-capture system, or a good localizer). The map is a fine grid of binary random variables mim_imi​, each true if cell iii is occupied, and the mapping problem is to compute

    p(m∣z1:t,x1:t).p(m \mid z_{1:t}, x_{1:t}).p(m∣z1:t​,x1:t​).

    A 100 m x 100 m floor at 5 cm has 4 million cells, so 24 000 0002^{4\,000\,000}24000000 possible maps: the joint posterior is intractable. The occupancy grid algorithm therefore assumes the cells are independent and estimates each one separately:

    p(m∣z1:t,x1:t)=∏ip(mi∣z1:t,x1:t).p(m \mid z_{1:t}, x_{1:t}) = \prod_i p(m_i \mid z_{1:t}, x_{1:t}).p(m∣z1:t​,x1:t​)=i∏​p(mi​∣z1:t​,x1:t​).

    The log-odds form: updates become additions

    Each cell is a static binary state, so its Bayes filter is the binary Bayes filter. Written in log odds, l=ln⁡p1−pl = \ln\frac{p}{1-p}l=ln1−pp​, the update is a simple addition. TLO1 asks you to discuss the occupancy grid mapping algorithm:

    Algorithm occupancy_grid_mapping({lt−1,i},xt,zt)(\{l_{t-1,i}\}, x_t, z_t)({lt−1,i​},xt​,zt​): for all cells mim_imi​:

    • if mim_imi​ is in the perceptual field of ztz_tzt​: lt,i=lt−1,i+inverse_sensor_model(mi,xt,zt)−l0l_{t,i} = l_{t-1,i} + \text{inverse\_sensor\_model}(m_i, x_t, z_t) - l_0lt,i​=lt−1,i​+inverse_sensor_model(mi​,xt​,zt​)−l0​

    with the prior l0=ln⁡p(mi=1)1−p(mi=1)l_0 = \ln\frac{p(m_i = 1)}{1 - p(m_i = 1)}l0​=ln1−p(mi​=1)p(mi​=1)​, zero for a prior of 0.5. The probability is recovered by p=1−1/(1+el)p = 1 - 1/(1 + e^{l})p=1−1/(1+el). Log odds avoid numerical problems near 0 and 1 and make each update O(1) per cell.

    The inverse sensor model for range finders

    TLO2 asks you to discuss the inverse measurement model for range finders. It is called inverse because it reasons from effect to cause: p(mi∣zt,xt)p(m_i \mid z_t, x_t)p(mi​∣zt​,xt​) rather than p(zt∣m,xt)p(z_t \mid m, x_t)p(zt​∣m,xt​). For a cell at range rrr and bearing ϕ\phiϕ from the sensor, find the beam kkk closest in bearing, then:

    1. If r>min⁡(zmax,ztk+α/2)r > \min(z_{max}, z_t^k + \alpha/2)r>min(zmax​,ztk​+α/2) or ∣ϕ−θk∣>β/2|\phi - \theta_k| > \beta/2∣ϕ−θk​∣>β/2: the cell is beyond the reading or outside the beam, return l0l_0l0​ (no information).

    3. If r≤ztkr \le z_t^kr≤ztk​: the beam passed through, return lfreel_{free}lfree​.

    α\alphaα is the thickness of obstacles and β\betaβ the beam width.

    Use cases and problems of occupancy grids

    Use cases
    Occupancy grids are the map format of ROS (nav_msgs/OccupancyGrid, saved as PGM plus YAML), of Nav2 costmaps and of most robot vacuums. They are used for localization (Chapter 6), planning (Chapter 2) and exploration, where the frontier between known free and unknown cells defines where to go next. OctoMap extends them to 3D with octrees for drones and manipulators.
    Problems
    • Known poses are assumed; with drifting odometry the map smears and walls double. This is why SLAM is needed.
    • Cell independence ignores that neighbouring cells of a wall are correlated, so maps are noisier than necessary; conflicting beams at grazing angles erase thin walls.
    • Memory grows with area over resolution squared.
    • Dynamic objects leave ghost trails unless updates are clamped.
    • Sensor artefacts: sonar's wide cone and specular reflections, LiDAR's failure on glass, all corrupt the map.

    7.3Simultaneous localization and mapping

    SLAM: a chicken-and-egg problem

    Simultaneous localization and mapping (SLAM) arises when the robot has neither a map nor its pose. Localization needs a map; mapping needs the poses. SLAM estimates both together from controls and measurements alone. There are two forms:

    Online SLAM: p(xt,m∣z1:t,u1:t)Full SLAM: p(x1:t,m∣z1:t,u1:t)\text{Online SLAM: } p(x_t, m \mid z_{1:t}, u_{1:t})\qquad \text{Full SLAM: } p(x_{1:t}, m \mid z_{1:t}, u_{1:t})Online SLAM: p(xt​,m∣z1:t​,u1:t​)Full SLAM: p(x1:t​,m∣z1:t​,u1:t​)

    Online SLAM is obtained from full SLAM by integrating out past poses. SLAM also has a discrete part, the correspondence between observed features and map features, which makes it harder than either localization or mapping alone.

    EKF SLAM: augment the state with the landmarks

    Review question 1 asks you to discuss the EKF algorithm for SLAM. EKF SLAM applies the EKF to online SLAM with a feature map and maximum-likelihood data association. The state vector stacks the pose and all NNN landmark positions:

    yt=(x, y, θ, m1,x, m1,y, …, mN,x, mN,y)T,dimension 3+2N,y_t = (x,\ y,\ \theta,\ m_{1,x},\ m_{1,y},\ \ldots,\ m_{N,x},\ m_{N,y})^T,\qquad \text{dimension } 3 + 2N,yt​=(x, y, θ, m1,x​, m1,y​, …, mN,x​, mN,y​)T,dimension 3+2N,

    with a (3+2N)×(3+2N)(3 + 2N) \times (3 + 2N)(3+2N)×(3+2N) covariance. Landmarks are static, so the motion model moves only the pose part. Measurements are range-bearing observations exactly as in EKF localization, except that the landmark positions are now unknowns in the state, so the measurement Jacobian has non-zero blocks for both the pose and the observed landmark. The key consequence: every observation correlates the pose with the landmark, and through the pose, landmarks with each other.

    Approximations and limiting assumptions of SLAM

    TLO3 and ESA question 8a ask for the approximations and limiting assumptions. For EKF SLAM write these:

    1. Gaussian noise and linearisation: motion and measurement models are linearised at the current estimate; large heading uncertainty makes the linearisation poor and the filter overconfident (inconsistent).
    2. Feature-based maps with point landmarks; the environment must contain distinct, extractable features and the raw data outside features is discarded.
    3. Correct data association: a single wrong correspondence can corrupt the whole map irreversibly. Provisional landmark lists and gating are used to protect against it.
    4. Quadratic complexity: each update touches the full covariance, O(N2)O(N^2)O(N2) time and memory. For N=1000N = 1000N=1000 landmarks the covariance has (2003)2≈4.0(2003)^2 \approx 4.0(2003)2≈4.0 million entries, updated at every measurement.
    5. Static world: landmarks are assumed not to move.
    6. Unimodal belief: it cannot represent ambiguity about which loop has been closed.

    Graph SLAM and the loop closure

    Graph-based SLAM solves full SLAM. Each pose is a node; each odometry reading is an edge constraining two consecutive nodes; each re-observation of a known place adds a loop-closure edge between distant nodes. The map is recovered by finding the configuration of nodes that minimises the sum of squared constraint errors weighted by their information matrices:

    x∗=arg⁡min⁡x∑ijeij(xi,xj)T Ωij eij(xi,xj).x^* = \arg\min_x \sum_{ij} e_{ij}(x_i, x_j)^T\,\Omega_{ij}\,e_{ij}(x_i, x_j).x∗=argxmin​ij∑​eij​(xi​,xj​)TΩij​eij​(xi​,xj​).

    The information matrix of this problem is sparse (each edge links two nodes), so sparse solvers such as g2o, GTSAM, Ceres and iSAM handle tens of thousands of poses, unlike the dense EKF.

    SLAM in practice

    Real-life examples
    Robot vacuums from iRobot, Roborock and others run LiDAR or visual SLAM on the device to map a home and clean room by room. ROS 2 users typically map with slam_toolbox (a graph-based 2D LiDAR SLAM) and then localize with AMCL on the saved map. Google Cartographer combines local scan matching into submaps with global loop closure. Warehouse integrators map a site once with SLAM, then run localization only during production.

    Problems in the field
    Wrong loop closures in repetitive environments fold maps; use robust kernels and geometric verification. Featureless corridors and glass defeat LiDAR scan matching. Long-term changes (moved racks) make old maps stale; lifelong SLAM updates or prunes nodes.

    7.5RGB-D SLAM

    SLAM with colour and depth cameras

    An RGB-D camera (Microsoft Kinect, Intel RealSense, Orbbec) provides a colour image and a per-pixel depth image, typically 640 x 480 at 30 Hz with useful range of about 0.3 to 5 m. RGB-D SLAM exploits both: visual features give distinctive data association (which LiDAR lacks), and depth gives metric 3D positions (which a monocular camera lacks).

    1. Feature extraction: ORB, SIFT or SURF keypoints and descriptors in the colour image, lifted to 3D using the depth at each pixel.
    2. Motion estimation: match features between frames and estimate the rigid transform with RANSAC; refine with ICP on the depth point clouds.
    3. Pose graph: keyframes become nodes; frame-to-frame transforms become edges; place recognition (bag of visual words) proposes loop closures.
    4. Optimisation: graph optimisation (g2o, iSAM) corrects the trajectory.
    5. Map: register point clouds, or fuse depth into a voxel map such as OctoMap or a truncated signed-distance field (KinectFusion).

    Strengths, limits and systems of RGB-D SLAM

    Criterion2D LiDAR SLAMRGB-D SLAM
    Map2D occupancy grid3D colour point cloud or voxels
    Range10-30 m0.3-5 m
    LightingIndependentColour features need light; depth fails in sunlight (structured light)
    Data associationGeometric onlyVisual descriptors: strong place recognition
    CostHigher sensor costLow sensor cost, higher compute
    Systems
    RTAB-Map (widely used in ROS), ORB-SLAM3 in RGB-D mode and ElasticFusion are established RGB-D SLAM systems. RGB-D sensors are common on mobile manipulators and service robots that need to see table tops and shelves, not just the floor plan.
    Limitations
    Short depth range and a narrow field of view give few constraints in large open spaces; depth noise grows roughly with the square of range; black, shiny and transparent surfaces return no depth; fast rotation blurs images. Robust systems fuse an IMU and wheel odometry to bridge these gaps.
